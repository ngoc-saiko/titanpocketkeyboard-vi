Fix: when the w-modifier transform actually changes the buffer, set `charModified = true` before returning, AND write the transformed result back into `buffer` (via `setBuffer(newStr)` or by clearing/appending) so the next keypress operates on the composed buffer "ơ", not the stale "o". Change the guard so that a 'd'-triggered transform (dd→đ) also sets `charModified = true`.     Remove the dead `val check = char != 'd'` line (234) — it is unused.

    Do NOT special-case the literal test inputs. Set the flag for the whole w-modifier transform class (Path 1) and the whole d-modifier transform class (Path 2). The reverseCharModifier map (lines 102-117) already enumerates every ơw→ow, ưw→uw, đd→dd, ăa→aa, âa→aa, etc. pattern; the only missing piece is charModified being true so the loop that consults that map runs.

    Do NOT alter the reverseCharModifier or charModifiers maps — the data is correct; only the flag-setting control flow is wrong.
